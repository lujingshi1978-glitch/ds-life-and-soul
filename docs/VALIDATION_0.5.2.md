# 0.5.2 验证记录

本版本包含此前完成的网站操作界面、快捷语音小字幕、长期关注生命周期，以及这次的启动重放修复。

## 冷启动与重复计费

后台思考的调用ID是每次模型调用生成的独立UUID，最终用量只记录一次。此前逐轮明细被归档后，旧思考日志重放会重新摄入这些调用，重复累加归档总量，并逐条压缩重写账本。0.5.2在明细和归档累计之间保留同一调用的去重边界，不改变普通会话的多步调用、重试和未见过的历史事件。

在一份真实用量日志的私人隔离副本中，18,781条记录、约5.35MB的思考日志连续冷读三次，耗时231、220、216毫秒。三次均未新增账目，账本字节和汇总总量保持一致。测试没有改写生产日志、调用模型或发送社交消息。以上数字是账本载入与历史重放阶段的测量，不是完整服务启动时间。

专项回归覆盖明细归档后的三次重启、新记录追加、普通会话的历史缺口与重试、UTF-8分块、日志截断、无效JSON和空记录。不会因为修复而清空或重新计算已有账本；此前可能发生的历史重复累计需要单独核对原始凭据，不能直接猜测扣减。

## 安装设置是否每次执行

在中文与空格路径的隔离目录完成一次安装后，使用真实本机临时HTTP进程替代DSH和桥接，连续执行两次普通启动。进程身份记录相同，未执行依赖安装；本机配置、角色选择、凭据、字幕设置和模拟记忆字节保持不变。

已有配置却缺少`.local/installation.json`时，普通启动明确报错并保留原文件，不会退回首次向导。显式`setup`仍是安装或修复入口；升级要保留原来的本机数据目录。
