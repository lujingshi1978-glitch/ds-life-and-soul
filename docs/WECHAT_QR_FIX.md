# 微信扫码二维码修复与旧版升级

0.4.3修复了0.4.0—0.4.2的微信扫码部署缺陷。报错中的 `integration-runtime/wechat/node_modules/qrcode` 是开发环境遗留路径，公开安装器没有创建该目录；这是程序打包遗漏，不是让使用者去寻找这一目录或填写QQ网关配置。

另一个问题是页面的Content-Security-Policy未允许内联二维码图片，即使生成了PNG也会被浏览器拦截。0.4.3仅在图片策略增加 `data:`，其余默认来源、脚本和样式策略保持。

## 新安装

使用0.4.3或更新的整合包，正常运行 `启动肥鱼.cmd`。二维码库 `qrcode@1.5.4` 已纳入核心锁文件，随核心依赖一起安装，不需要额外建立微信Node运行环境。

## 已安装旧版

1. 在旧安装目录运行 `stop.cmd`，停止这份肥鱼和DSH。手动启动的服务需在原终端停止。
2. 下载新版，将含根目录 `package.json` 的那一层源码文件复制到原安装根目录，更新源码及锁文件。不要再嵌套一层新版文件夹。
3. 保留原有 `.local`、`.runtime`、`packages/feiyu/config.json`、`packages/feiyu/state`、`packages/feiyu/cognition-v3` 和账号目录。不要删除旧目录后拿干净包代替私人数据。
4. 双击新版 `scripts/修复核心依赖.cmd`，等待完成。它会按锁文件执行核心 `npm ci --ignore-scripts`，安装新增依赖；不重建角色、记忆、账号或模型凭据。
5. 重新运行 `启动肥鱼.cmd`，打开“世界与连接”，点击“扫码连接微信”。

命令行等价入口，在安装根目录执行：

```powershell
node scripts/deploy.mjs repair-core
node scripts/deploy.mjs start
```

修复入口发现配置中的服务端口仍在监听时会拒绝操作，不强制结束未知进程。启动器也会检查声明的核心依赖；缺失或版本不符时给出修复提示，避免等点扫码后才出现Node模块路径错误。

只给旧版手工安装一个 `qrcode` 包不能消除旧源码的硬编码路径。需要先更新源码与锁文件，再安装依赖。
